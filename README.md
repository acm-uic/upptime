With [Upptime](https://upptime.js.org), you can get your own unlimited and free uptime monitor and status page, powered entirely by a GitHub repository. We use [Issues](https://github.com/acm-uic/upptime/issues) as incident reports, [Actions](https://github.com/acm-uic/upptime/actions) as uptime monitors, and [Pages](https://acm-uic.github.io/upptime) for the status page.

Monitoring secrets are explicitly allowlisted by `secrets` in `.upptimerc.yml`. The list is empty because the monitored endpoints are public; the GitHub token is passed separately. If authenticated checks or secret-based notifications are added, list only their required secret names there and regenerate the workflows. Do not restore `toJson(secrets)`: it exposes every secret to the action and may cause GitHub to hold workflow runs for approval.

### GitHub App authentication

The generated Upptime workflows support a dedicated GitHub App. The default `GITHUB_TOKEN` cannot push changes to `.github/workflows`, so automatic template updates require the App token (or a separately configured `GH_PAT`).

1. Create a GitHub App with repository **Contents**, **Workflows**, **Issues**, and **Actions** permissions set to **Read and write**. Metadata read access is automatic. No organization permissions or webhook subscriptions are needed.
2. Install the App on **only `acm-uic/upptime`**.
3. Under repository **Settings > Secrets and variables > Actions**, create a repository variable named `GH_APP_ID` containing the App's **Client ID** (not its numeric App ID), and a repository secret named `GH_APP_PRIVATE_KEY` containing a generated PEM private key. Upload the key directly to GitHub; never commit it.
4. Merge the workflow changes, then dispatch a new **Setup CI** run on `main`. Re-running the earlier failed run would use its old workflow, which does not create an App token.

The workflows create a short-lived installation token before checkout and use it for GitHub operations. They clear the private-key environment variable before running Upptime, and the token action revokes its token when the job ends. Leave `secrets: []` unchanged: App authentication is wired separately and does not require exposing the private key through `SECRETS_CONTEXT`. Future Upptime template updates retain this built-in authentication.
